# 출시 점검

사람이 알려 준 주소(예: 내 Render 주소)를 기준으로 봅니다. 주소를 알려 주지 않았으면 먼저 묻습니다.

## 점검 항목

1. 미리보기: `static/index.html`의 OG 태그 4개(`og:title`, `og:description`, `og:image`, `og:url`)가 있고 `og:url`이 내 주소인지 봅니다.
2. 보안, 사용자 관점: 인증·인가가 빠진 곳, 남의 데이터에 접근할 수 있는 곳, 응답에 들어간 개인정보.
3. 보안, 서비스 관점: 코드·저장소에 들어간 키, 오류 응답에 드러난 내부 정보, 요청 제한.
4. 성능·비용: 페이지 나눔, 필요한 칸만 돌려주는지, 같은 일을 반복하지 않는지.
5. 데이터: 저장한 데이터를 잃지 않게 백업이나 오래 남는 DB가 있는지.

## 보고 모양

항목마다 표 한 줄로 씁니다.

| 항목 | 상태 | 근거 |
|---|---|---|

- 상태는 "통과", "문제", "미확인" 중 하나입니다.
- 확인하지 않은 항목은 통과로 보지 말고 "미확인"으로 적습니다.

## 판단

표 아래에 아래 셋 중 하나를 고르고 이유를 두 줄 안쪽으로 씁니다.

- 출시 중단: 사용자 데이터가 새거나 남이 고칠 수 있는 문제가 있습니다.
- 조건부 출시: 알려진 문제가 있지만 조건을 지키면 내놓을 수 있습니다. 조건을 적습니다.
- 출시 후 개선: 지금 내놔도 되고, 고칠 것은 다음에 합니다.

## 하지 말 것

- 파일을 고치지 않습니다. 보고만 합니다.
- 실행하지 않은 확인을 실행한 것처럼 쓰지 않습니다.
