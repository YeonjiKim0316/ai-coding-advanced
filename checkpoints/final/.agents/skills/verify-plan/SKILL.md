# 검증 계획 먼저

기능을 만들기 전에, 무엇으로 맞는지 확인할지부터 정합니다.

## 순서

1. 사람이 알려 준 스펙 파일을 읽습니다. 알려 주지 않았으면 어떤 스펙인지 먼저 묻습니다.
2. 스펙의 주장을 한 줄씩 뽑습니다. 주장 하나는 확인할 수 있는 문장 하나입니다.
3. `verification-plan.md`에 표를 씁니다. 열은 아래 순서입니다.

| 번호 | 스펙의 주장 | 증거 종류 | 확인 방법 | 상태 |
|---|---|---|---|---|

4. 증거 종류는 아래에서 고릅니다.
   - 계산·규칙: 단위 테스트
   - API 연결(요청 → 응답): 통합 테스트
   - 화면: 화면 캡처
   - 바깥으로 나가는 일(전송, 저장, 삭제): 로그
5. 확인할 수 없는 주장이 있으면 "확인 못 함"으로 적고 이유를 한 줄 씁니다.
6. 표를 보여 주고 멈춥니다. 사람이 "승인"이라고 하기 전에는 코드와 테스트를 쓰지 않습니다.

## 하지 말 것

- 표에 없는 주장을 테스트로 만들지 않습니다.
- 스펙에 없는 기능을 계획에 넣지 않습니다.
- 계획만 쓰고 파일은 `verification-plan.md` 하나만 만듭니다.
