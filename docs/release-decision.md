> 예시입니다. `$release-check <내 Render 주소>`의 보고를 읽고, 내 판단과 근거를 적습니다.

## 점검 결과

| 항목 | 상태 | 근거 |
|---|---|---|
| 미리보기 | 통과 | OG 태그 4개가 있고, 카카오톡 나에게 보내기에서 제목과 그림이 보였습니다. |
| 보안: 인증·인가 | 통과 | 리뷰 API는 토큰이 없으면 401, 남의 리뷰는 403입니다. 권한 테스트가 있습니다. |
| 보안: 키 | 통과 | `SECRET_KEY`는 `.env`와 Render 환경변수에만 있습니다. 저장소 검색에 값이 없습니다. |
| 보안: 오류 응답 | 통과 | 500은 `request_id`만 돌려주고 내부 정보를 담지 않습니다. |
| 보안: 요청 제한 | 미확인 | 로그인 시도 횟수를 막는 코드가 없습니다. 확인하지 않았습니다. |
| 성능·비용 | 통과 | 목록은 페이지로 나뉘고 `size`는 100까지입니다. |
| 데이터: 백업 | 문제 | Render 무료 서비스는 재배포하면 `data/app.db`가 사라집니다. 백업이 없습니다. |

## 내 판단: 조건부 출시

- 근거: 남의 데이터를 볼 수 있는 문제는 없습니다. 다만 저장한 리뷰가 재배포 때 사라지고, 로그인 시도 제한을 확인하지 못했습니다.
- 조건: 사용자에게 "저장한 리뷰는 사라질 수 있다"고 알립니다. 오래 남는 DB로 옮기는 일을 다음 할 일 맨 위에 둡니다.

## 출시 후 개선

1. 오래 남는 DB로 옮기기 (숙제)
2. 로그인 시도 제한
